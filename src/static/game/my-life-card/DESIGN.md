# 人生手牌：卡牌对战式模拟人生设计上下文

这份文档用于在重启对话后快速恢复上下文。当前游戏位于 `src/static/game/my-life-card/`，是一个不依赖外部框架的纯静态网页游戏。

## 一句话概括

《人生手牌》现在采用卡牌对战式交互：命运每回合像对手一样亮出事件牌，玩家从 5 张手牌中选择一张回应牌，把牌打到战场中央，与命运进行一次 Clash 结算，再通过逐句对话反馈听见选择的回声。

## 文件结构

- `index.html`：对战牌桌结构，包括命运对手区、中央战场、玩家手牌、战后反馈和战局记录。
- `styles.css`：暗色战术卡桌视觉，包含命运牌、费用球、手牌、战场槽位、VS 标识和响应式布局。
- `game.js`：完整对战式状态机、命运牌库、玩家牌库、行动力、Clash 结算、反馈生成和结局判定。
- `DESIGN.md`：本上下文摘要文件。

## 当前交互目标

新版不是简单“抽三选一”，而是参考卡牌对战游戏的手感：

1. **对手意图可见**：命运先翻开事件牌，显示标题、威胁值、压力效果和弱点类型。
2. **玩家从手牌回应**：玩家持有 5 张手牌，每张牌有费用、Clash 点数、类型和数值效果。
3. **中央战场对撞**：选中的牌会预览到玩家槽位，点击后打入战场，与命运牌进行 Clash。
4. **结算有层次**：根据手牌点数、克制类型、当前状态加成和命运威胁，得出“压制命运 / 稳住局面 / 被命运反击”。
5. **反馈逐句推进**：战后反馈以对话方式逐句展开，而不是一次性弹出。

## 每回合流程

游戏状态字段 `state.phase` 控制流程：

- `reveal`：命运揭示。
  - 显示“开始回合 · 揭示命运”按钮。
  - 点击后调用 `startRound()`。
  - 随机抽取一张 `fateDeck` 中的命运事件牌。
  - 将行动力重置为 3，并补充玩家手牌到 5 张。
  - 状态进入 `respond`。
- `respond`：手牌应对。
  - 玩家点击一张行动力足够的 `.life-card`。
  - 中央玩家槽位显示预备中的牌。
  - `clash-forecast` 显示预估结果：你的 Clash 点数 vs 命运威胁值。
  - 点击“打到战场 · 结算 Clash”后调用 `resolveClash(card)`。
- `feedback`：战后反馈。
  - 出牌后会结算卡牌效果、命运压力、每回合生活成本。
  - 反馈对话由 `feedbackIndex` 控制，每点一次按钮展示下一句。
  - 读完后进入下一回合，或第 12 回合后进入结局。
- `ended`：人生小结。
  - 第 12 回合反馈结束后调用 `buildEnding()`。
  - 页面显示最终结局，按钮变成“本局已完成”。

## 数值系统

追踪 6 个角色属性：

- `money`：现金，初始 2400，范围 -2000 到 12000。
- `health`：健康，初始 72，范围 0 到 100。
- `mood`：情绪，初始 64，范围 0 到 100。
- `skill`：能力，初始 38，范围 0 到 100。
- `relationship`：关系，初始 42，范围 0 到 100。
- `stress`：压力，初始 28，范围 0 到 100。

所有数值通过 `clampStat()` 限制范围。

## 行动力与手牌

- `maxEnergy = 3`，每回合开始重置为 3。
- `startingHandSize = 5`，回合开始会补牌到 5 张。
- 玩家牌有 `cost` 和 `power`：
  - `cost` 决定是否能在当前行动力下打出。
  - `power` 参与 Clash 点数计算。
- 打出的牌会从 `hand` 移除，进入 `discardPile`。
- `drawPile` 为空时，会把 `discardPile` 洗回抽牌堆。

## 命运牌设计

`fateDeck` 是“对手牌库”，当前包含：

- 房租和账单一起压来：现金压力。
- 身体发出刺耳提醒：健康压力。
- 一个位置突然空出来：职业机会。
- 热闹都离你很远：关系低潮。
- 你开始怀疑自己是不是不够好：内心质疑。
- 有人递来一张看似翻身的门票：高风险诱惑。

每张命运牌包含：

- `type`：事件类型。
- `title`：事件标题。
- `intent`：本回合意图说明。
- `threat`：威胁值，用于 Clash 对比。
- `pressure`：如果处理不好会造成的数值压力。
- `weakness`：被哪些玩家牌类型克制。

## 玩家牌设计

`cardDeck` 仍保留人生主题，但新增卡牌对战属性：

- `cost`：费用，消耗行动力。
- `power`：Clash 基础点数。
- `type`：用于匹配命运弱点。
- `effects`：打出后带来的直接资源变化。
- `dialogue`：反馈环节插入的角色对话。

当前玩家牌包括事业、成长、关系、休整、机会、家庭、冒险、生存、自我、社交、健康、创造等维度。

## Clash 结算

核心函数是 `evaluateClash(card, fateCard)`。

Clash 点数来自：

- 玩家牌 `power`。
- 如果玩家牌类型命中命运牌 `weakness`，获得 +3 克制加成。
- 能力高时，事业 / 成长 / 创造 / 机会类牌可获得额外加成。
- 关系高时，关系 / 社交 / 家庭类牌可获得额外加成。
- 压力过高时，会产生负面修正。

结果分三档：

- `breakthrough` / 压制命运：玩家点数至少比威胁高 3。
- `hold` / 稳住局面：玩家点数达到威胁值。
- `wound` / 被命运反击：玩家点数低于威胁值。

命运压力会根据结果被折减：

- 压制命运：只承受约 35% 压力，并额外增加情绪和能力。
- 稳住局面：承受约 65% 压力。
- 被命运反击：承受完整压力，并额外增加压力。

## 页面布局

主要区域：

- `.hero`：游戏标题、轮次、年龄季节、行动力和重开按钮。
- `.status-grid`：现金、健康、情绪、能力、关系、压力。
- `.phase-panel`：四段流程：命运揭示、手牌应对、战场结算、对话反馈。
- `.arena-layout`：三栏对战区域：命运对手、中央战场、战后反馈。
- `.hand-panel`：玩家 5 张手牌。
- `.log-panel`：每回合 Clash 记录。

## 视觉方向

新版视觉是“暗色战术卡桌”：

- 命运牌像敌方单位，使用红橙色威胁边框和威胁角标。
- 玩家牌像手牌，有费用球、类型、标题、Clash 点数和效果标签。
- 中央战场有命运槽位、玩家槽位和 VS 圆标。
- 选中手牌会上浮，模拟卡牌对战中的选牌手感。
- 桌面背景带网格和斜向光纹，强化牌桌氛围。
- 响应式布局：桌面三栏，平板两栏，手机单栏。

## 关键函数速查

- `startRound()`：揭示命运、重置行动力、补牌到 5 张。
- `drawFateCard()`：随机抽取命运牌。
- `selectCard(cardId)`：选择玩家手牌并更新预估。
- `resolveClash(card)`：打出手牌、移入弃牌堆、结算 Clash。
- `evaluateClash(card, fateCard)`：计算胜负档位。
- `applyFatePressure(fateCard, clash)`：按 Clash 结果折算命运压力。
- `applyRoundPressure(clash)`：应用每回合生活成本。
- `buildFeedback(card, fateCard, clash, changes)`：生成战后逐句反馈。
- `finishRound()`：进入下一回合或结局。
- `buildEnding()`：根据最终状态生成结局。
- `render()`：统一渲染入口。

## 验证建议

改动后应至少验证：

1. `node --check game.js` 通过。
2. 页面能打开且控制台无错误。
3. 初始状态显示 5 张手牌，但不能出牌，需先揭示命运。
4. 点击“开始回合 · 揭示命运”后出现命运牌和可选手牌。
5. 点击手牌后，中央玩家槽位显示预览，并显示 Clash 预估。
6. 点击“打到战场 · 结算 Clash”后进入反馈，对话逐句推进。
7. 反馈结束后能进入下一回合。
8. 自动跑完 12 回合后能进入结局，并产生 12 条战局记录。
